# Deployment

## Two modes

| | LOCAL REAL-DATA MODE | PUBLIC DEMO MODE |
|---|---|---|
| Where | Your own machine (`START-GRIDINTEL.bat`, or `run_backend.bat`) | Hosted service (Render) |
| Data | Private HVPNL workbooks in `data/raw/`, trained locally | An uploaded artifact bundle: model artifacts plus derived values. No workbooks. |
| Verbatim Excel cell text | Shown in Data Explorer | Stripped from the bundle and never served |
| Demo logins | On (`operator` / `hvpnl2026`) | Off (`DEMO_USERS_ENABLED=false`). ADMIN set in the dashboard. |
| Label in the UI and in `/health` | `LOCAL REAL-DATA MODE` | `PUBLIC DEMO MODE` |

`DATA_MODE=local|public` sets the mode. If it's blank, the mode is `local` when `data/raw/*.xlsx` exist and `public` otherwise.

## Architecture (hosted)

```
GitHub (TanviSaraswat8/gridintel) ──push──► GitHub Actions CI ──► GHCR image (ghcr.io/tanvisaraswat8/gridintel-api)
        │                                  lint · parse · i18n check · tests (Postgres+Redis) · Alembic on Postgres
        │                                  · mobile web build · Docker build + smoke test (public mode, no .xlsx)
        └──autoDeploy──► Render web service "gridintel" (Docker, free, Singapore)
                           ├─ FastAPI  /api/v1 · /health · /ready · /docs · /metrics
                           ├─ Web      /  (landing)  ·  /app  (command center)
                           ├─ Mobile   /mobile  (Expo web build, calls its own origin)
                           └─ Render PostgreSQL "gridintel-db" (users, audit, notes, alerts, artifact bundle)
```

- **One origin.** The web app, the mobile web build and the API share one HTTPS origin. CORS defaults to that origin (`RENDER_EXTERNAL_URL`). Production refuses `*`. Auth is a JWT bearer header, not cookies, so `allow_credentials=False`.
- **Redis is not provisioned.** There's one instance, so the in-memory cache and replay state are enough. Set `REDIS_URL` if you scale out.
- **Models.** Training needs about 1 GB of RAM, more than the free instance has, so the server doesn't train (`TRAIN_ON_START=false`). An ADMIN uploads the bundle once. It's stored in PostgreSQL and restored on every start, including after a free-plan sleep.

## Live instance

`https://gridintel-6gce.onrender.com` (Render service `gridintel`, database `gridintel-db`, Singapore, free plan).

## Steps

1. **Render account.** Sign up at render.com with GitHub, and allow Render to read the `gridintel` repository.
2. **Blueprint.** In the Render dashboard, choose **New → Blueprint** and pick `TanviSaraswat8/gridintel`. `render.yaml` creates the web service and the database. When asked, set:
   - `ADMIN_USERNAME`: your choice.
   - `ADMIN_PASSWORD`: a long, unique password. It's hashed on first start. Never commit it.
   `JWT_SECRET` is generated by Render, and `DATABASE_URL` is wired from the database.
3. **Wait for the first deploy** (about 5–8 minutes). `https://<service>.onrender.com/health` should return `"status":"ok"` and `"data_mode":"PUBLIC DEMO MODE"`. Until the bundle is uploaded, `/ready` returns 503 with `AWAITING DATA`.
4. **Upload the bundle.** On the local machine, run `python scripts/package_artifacts.py`, which writes `dist/gridintel-artifacts.tar.gz`. Open `https://<service>.onrender.com/app`, sign in as the ADMIN, choose the file on the **Awaiting data** screen and upload it. `/ready` then returns 200. A CLI alternative is `python scripts/package_artifacts.py --upload https://<service>.onrender.com --username <admin>`, which prompts for the password.
5. **Optional auto-deploy hook.** Render already redeploys on every push (`autoDeploy: true`). To deploy only after CI passes, turn auto-deploy off, copy the service's Deploy Hook URL into the GitHub secret `RENDER_DEPLOY_HOOK`, and `deploy.yml` will call it.

## Environment variables (hosted)

| Variable | Value | Source |
|---|---|---|
| `APP_ENV` | `production` (enforces JWT secret, no `*` CORS, HSTS) | render.yaml |
| `DATA_MODE` | `public` | render.yaml |
| `DATABASE_URL` | Render PostgreSQL connection string | render.yaml (from database) |
| `REDIS_URL` | unset (in-memory) | — |
| `JWT_SECRET` | generated | render.yaml |
| `JWT_EXPIRE_MINUTES` | 480 (default) | — |
| `CORS_ORIGINS` | unset → `RENDER_EXTERNAL_URL` | Render |
| `DATA_ROOT` / `MODEL_PATH` / `REPORTS_DIR` | `/data`, `/models`, `/models/reports` | render.yaml |
| `TRAIN_ON_START` | `false` | render.yaml |
| `DEMO_USERS_ENABLED` | `false` | render.yaml |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | set by you in the dashboard | Render dashboard |

## Security checklist

- Passwords are hashed with PBKDF2. JWTs expire (480 min). Roles are ADMIN, ENGINEER, OPERATOR and VIEWER.
- Rate limits apply globally and on login. Inputs are validated by Pydantic and query bounds. Bundle uploads accept allowed paths only, no links, and have size caps.
- Responses carry a CSP, X-Frame-Options DENY, nosniff, Referrer-Policy and, in production, HSTS. Logs are structured JSON with request IDs.
- No debug mode (uvicorn without `--reload`). There are no secrets in the repository or the image. CI checks that the image contains no `.xlsx`/`.xls`.

## Alternatives

The same image runs on Railway, Fly.io or any container host with the variables above. `docker-compose.prod.yml` runs API + PostgreSQL + Redis on one server. To serve the web app from a separate static host, use Vercel with root `frontend/` and `API_URL` set to the API URL, and add that host to `CORS_ORIGINS`.
