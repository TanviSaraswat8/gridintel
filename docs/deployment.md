# Deployment

Target: **API on Render (Docker) + managed PostgreSQL + Redis**, **web on Vercel**, **mobile via Expo**. Any container host (Railway, Fly.io, AWS ECS) works with the same image and variables.

## 0. Prerequisites
- GitHub repository containing this project (private data is git-ignored).
- Accounts: Render (or equivalent) and Vercel. Expo account optional.

## 1. API (Render Blueprint)
1. Render Dashboard → **New → Blueprint** → select the repository. `render.yaml` creates `gridintel-api` (Docker, 1 GB disk at `/data`), `gridintel-db` (PostgreSQL) and `gridintel-redis`.
2. Set the variables marked `sync: false`:
   - `CORS_ORIGINS` = your Vercel URL, e.g. `https://gridintel.vercel.app`
   - `API_URL` = the Render service URL, e.g. `https://gridintel-api.onrender.com`
   - `ADMIN_USERNAME`, `ADMIN_PASSWORD` (stored hashed on first start)
   - Optionally `DEMO_USERS_ENABLED=false` for a non-demo deployment.
   `JWT_SECRET` is generated by Render.
3. Upload the private HVPNL workbooks to the disk at `/data/raw/` (Render Shell → `mkdir -p /data/raw`, then upload via `scp`/Render disk tools, or build a private image). On first start with no models, the API trains them (~2–3 min); `/ready` turns 200 when done.
4. Check `https://<api>/health`, `/ready`, `/docs`.

The container runs `alembic upgrade head` before starting uvicorn.

## 2. Web (Vercel)
1. Vercel → **Add New Project** → same repository → **Root Directory: `frontend`**.
2. Environment variable `API_URL` = Render API URL. Build command and output come from `frontend/vercel.json` (`node build-config.mjs` writes `config.js`).
3. Deploy. `/` is the landing page, `/app` the Command Center.

## 3. Mobile (Expo)
- Development: `cd mobile && npm install && EXPO_PUBLIC_API_URL=https://<api> npx expo start` → Expo Go (SDK 57).
- Shareable build: `npx eas-cli build -p android --profile preview` (requires an Expo account), or use the browser build served by the API at `https://<api>/mobile`.

## 4. CI/CD (GitHub Actions)
- `ci.yml`: lint (ruff) → type/parse checks → tests with coverage (synthetic fixture, PostgreSQL + Redis services) → Alembic migration on PostgreSQL → mobile web build → Docker build (pushed to GHCR on `main`).
- `deploy.yml`: after CI succeeds on `main`, triggers the Render deploy hook and deploys the web app to Vercel. Repository secrets: `RENDER_DEPLOY_HOOK`, `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`. Missing secrets → the step is skipped, not failed.

## 5. Environments
| | development | staging | production |
|---|---|---|---|
| `APP_ENV` | development | staging | production |
| DB | SQLite / compose Postgres | managed Postgres | managed Postgres |
| `JWT_SECRET` | ephemeral | set | set (≥ 32 chars, enforced) |
| `CORS_ORIGINS` | `*` | staging web URL | explicit origins (enforced) |
| Demo users | on | on | off unless demonstrating |

## 6. Single host (Docker Compose)
```bash
docker compose -f docker-compose.prod.yml --env-file .env.production up -d
docker compose -f docker-compose.prod.yml cp ./data/raw/. api:/data/raw/
```
